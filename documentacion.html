Panorama general

El sistema es una aplicacion contable de una sola pagina. La estructura es simple a proposito: una capa de rutas para cada vista, un store central para el estado y utilidades separadas para calculos, PDF y validacion.

En la interfaz se mueven partidas, cuentas, alertas, reportes y la configuracion de la empresa. La mayor parte de las pantallas no calculan por su cuenta; consultan el store y reutilizan helpers para no duplicar logica.

Lectura rapida: si quieres entender el sistema con poco esfuerzo, sigue este orden: App.tsx -> store/useStore.ts -> pages/Reportes.tsx -> utils/validation.ts -> utils/pdfExport.ts.

Estado global

El store vive en src/store/useStore.ts y usa Zustand con persistencia. Esto significa que la app no depende de una base de datos externa para arrancar; guarda el estado local y lo recupera al volver a abrirse.

Datos principales

accounts, entries, alerts y empresa son las piezas que sostienen casi toda la interfaz.

Preferencias de UI

theme y sidebarCollapsed tambien se persisten, para que la experiencia siga igual al recargar.

Acciones clave

Hay funciones para iniciar el store, cargar datos de ejemplo, agregar partidas, borrar cuentas, limpiar datos y actualizar la empresa.

Dato importante

La accion clearData() restablece partidas y alertas, pero conserva el catalogo base de cuentas. No es un borrado brutal de todo.

Modelos de datos

El modelo es bastante directo. Las cuentas describen la estructura contable, las partidas guardan el movimiento y la empresa alimenta los encabezados, reportes y respaldos.

Objeto Campos relevantes Uso real
Account codigo, nombre, tipo, naturaleza, nivel, cuenta_padre, permite_movimientos, estado Alimenta catalogo, reportes, validacion y calculo de saldos.
JournalEntry numero, fecha, concepto, estado, lineas, creada_en, actualizada_en Es la unidad operativa del sistema y la base de casi todos los reportes.
EntryLine cuenta_codigo, debe, haber, concepto_linea Permite repartir una partida entre varias cuentas con control de montos.
Empresa razon_social, nit, direccion, telefono, email, moneda, simbolo_moneda, periodo_inicio, periodo_fin, ciclo Aparece en encabezados, reportes PDF y ahora tambien en el backup JSON.

Reportes y respaldo

La pantalla de reportes es la puerta de salida del sistema. Desde ahi se exporta PDF, CSV y JSON. Los PDFs toman datos del store, mientras que el JSON empaqueta el estado que interesa restaurar despues.

PDF

Los generadores viven en src/utils/pdfExport.ts. Cada uno recibe partidas y cuentas, arma el documento y usa la configuracion de empresa para el encabezado.

CSV

El CSV sale de src/pages/Reportes.tsx y se arma con una fila por linea de partida. Es util cuando alguien quiere abrir los movimientos en Excel sin tocar el sistema.

JSON

El respaldo incluye entries, accounts y empresa, ademas de metadatos como exportedAt y version.

Compatibilidad

Los respaldos viejos siguen funcionando. Si no traen empresa, la importacion respeta la configuracion actual del sistema.

Importacion segura

La validacion de backups no se limita a checar que el JSON "abra". El archivo se parsea con un reviver que bloquea claves peligrosas, y despues cada objeto pasa por validacion estricta.

Validacion Que evita Donde vive
Tamano maximo de importacion Archivos gigantes y bloqueos al leer en memoria. src/utils/validation.ts
Reviver con claves prohibidas Prototype pollution con __proto__, constructor y prototype. src/utils/validation.ts
Longitudes maximas Campos desbordados y payloads innecesarios. src/utils/validation.ts
Chequeo de cuentas referenciadas Partidas con lineas que apuntan a cuentas inexistentes. src/utils/validation.ts
Detalle importante: la importacion nueva no rompe los archivos viejos. Si el backup no trae empresa, el sistema restaura partidas y cuentas, pero conserva la empresa que ya estaba cargada.

Como se usa en la practica

El recorrido normal es bastante limpio: el usuario entra al dashboard, revisa el estado general, registra partidas, consulta libros, corrige alertas y al final exporta reportes o un respaldo.

Cuando se abre la app

App.tsx inicializa el store y el tema. El layout se encarga de la barra lateral, el encabezado, el modo oscuro y los atajos de navegacion.

Cuando se crea una partida

La partida se guarda en el store, luego los reportes y balances la toman desde ahi. No hay una segunda fuente de verdad escondida.

Cuando se exporta

El usuario no exporta una vista "bonita"; exporta el estado real de cuentas, partidas y empresa. Eso hace que el respaldo sirva para volver a cargar el sistema.

Cuando algo no cuadra

Primero revisa Auditoria, luego Balance de Saldos y por ultimo la partida concreta en Libro Diario.
