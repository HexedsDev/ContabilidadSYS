Antes de empezar

El sistema trabaja con tres piezas que conviene tener presentes desde el inicio: cuentas, partidas y datos de empresa. Si esas tres cosas estan en orden, el resto fluye bastante bien.

Lo que guarda la aplicacion

Cuentas, partidas, alertas, configuracion de empresa, tema visual y estado de la barra lateral.

Lo que veras siempre

Un layout fijo con menu lateral, barra superior, avisos, accesos a libros y rutas de configuracion.

Consejo: si acabas de abrir el sistema, mira primero si el nombre de la empresa y el ciclo contable son correctos en la barra superior. Eso te ahorra dudas mas adelante.

Como moverse por el sistema

A la izquierda tienes el menu principal. Cada grupo tiene una funcion bastante clara: operacion, libros, estados, configuracion y reportes.

Zona Para que sirve
Barra lateral Mueve entre modulos sin perder el contexto de la pantalla actual.
Barra superior Muestra el ciclo contable, el numero de partidas y el acceso al tema.
Botones de accion Abren formularios, cargan demo, exportan archivos o limpian datos.
Si usas movil: el menu se abre desde el icono superior izquierdo. No hace falta buscar nada mas raro.

Dashboard

Esta es la pantalla de entrada. Resume si la contabilidad esta cuadrada, cuantas partidas hay, cuantas alertas siguen abiertas y cual es el estado general del periodo.

Que mirar primero

Si el indicador de ecuacion contable no cuadra, conviene revisar partidas y alertas antes de seguir capturando.

Que hacer desde aqui

Puedes cargar datos de ejemplo, crear una nueva partida o ir directo al libro diario para revisar registros recientes.

Registrar partidas

La pantalla de registro es donde nace el movimiento contable. Ahí se capturan fecha, concepto, estado, observaciones y las lineas de debe/haber.

Flujo recomendado

1. Elegir la fecha

Usa la fecha real del movimiento, no la del dia en que te acordaste de registrarlo.

2. Escribir el concepto

Hazlo claro y corto. Sirve para ubicar la partida despues sin leer toda la historia.

3. Agregar lineas

Cada linea apunta a una cuenta y lleva debe o haber. Si una linea no tiene cuenta correcta, la partida despues se nota rara en reportes.

4. Revisar antes de guardar

Asegurate de que el total del debe y el total del haber queden coherentes. Esa pequena revision vale oro.

Regla simple: si la partida no parece entendible cuando la lees en voz alta, probablemente conviene reescribir el concepto antes de guardarla.

Consultar libros

Los libros no son una pantalla decorativa. Te sirven para comprobar que lo registrado realmente tiene sentido. Si algo se ve mal aqui, casi seguro tambien se vera mal en reportes.

Libro Diario

Muestra las partidas en orden cronologico. Es el mejor lugar para revisar un asiento especifico.

Libro Mayor

Agrupa por cuenta y deja ver el movimiento acumulado. Sirve para seguir un saldo sin recorrer todo el diario.

Balance de Saldos

Te ayuda a validar la fotografia general del periodo antes de sacar estados financieros.

Auditoria

Reune alertas y observaciones. Si algo no cuadra, esta pantalla suele dar una pista bastante util.

Exportar reportes

La pantalla de reportes sirve para sacar informacion ya armada: PDF para entregar o imprimir, CSV para hoja de calculo y JSON para respaldo tecnico.

Formato Uso normal Cuida esto
PDF Estados, libros y reportes formales. Que la empresa y el ciclo esten correctos en el encabezado.
CSV Analisis rapido en Excel o LibreOffice. Que las fechas y conceptos tengan sentido para quien lo abra.
JSON Respaldo completo y restauracion del sistema. Guardar una copia fuera del equipo si el dato es importante.

Configurar la empresa

La pantalla de configuracion guarda los datos que aparecen en encabezados, reportes y respaldos. No es solo un formulario administrativo; afecta lo que se imprime y lo que se restaura.

Datos obligatorios

Razon social, NIT, direccion, moneda, simbolo y periodo fiscal deben quedar coherentes para no ver reportes "a medias".

Que cambia al guardar

Se actualiza el encabezado del sistema y los PDF usan esa informacion cuando se exportan.

Respaldos e importacion

El respaldo JSON ahora incluye partidas, cuentas y configuracion de empresa. Eso permite restaurar la base contable sin reconstruir todo a mano.

Cuando exportas

Se genera un archivo con el estado actual. Conviene ponerle una copia de seguridad fuera del equipo si vas a usarlo para trabajo serio.

Cuando importas

Si el archivo trae empresa, se restaura tambien. Si no la trae, el sistema conserva la configuracion actual y solo recupera cuentas y partidas.

Antes de abrir un archivo

Asegurate de que venga de una fuente confiable. El sistema valida bastante, pero la costumbre de revisar no sobra.

Buen habito

Haz un respaldo antes de importar otro. Es la manera mas simple de evitar un susto por un archivo viejo o incompleto. 

{
  "entries": [ ... ],
  "accounts": [ ... ],
  "empresa": { ... },
  "exportedAt": "2026-05-22T00:00:00.000Z",
  "version": "2"
}

Problemas comunes

Esta parte te ahorra tiempo cuando el sistema no hace exactamente lo que esperabas.

Situacion Que revisar
La partida no aparece donde la esperabas Revisa la fecha, el estado y si guardaste realmente el registro.
Un PDF sale con datos viejos Abre la configuracion de empresa y confirma que guardaste los cambios.
El JSON importado no restaura todo Puede ser un backup viejo; si no trae empresa, el sistema deja la actual tal como estaba.
Ves alertas en auditoria Entra al libro diario y sigue la partida señalada hasta encontrar la cuenta o monto raro.
Cierre honesto: el sistema no intenta adivinar por ti. Si los datos de entrada estan bien, los reportes salen limpios; si algo se capturo mal, la pista suele estar en la partida original.

Resumen corto

Abres el dashboard, registras la partida, revisas libros, corriges si hace falta y al final exportas o respaldas. Si sigues ese orden, el sistema se siente bastante natural.
